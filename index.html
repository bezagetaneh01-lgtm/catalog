How the tables connect

Almost every join in this mart uses one of two keys:

  • LEAK_ID — connects a leak (DT_LEAKS) to its readings, grade history, extent, status history, and work orders.
  • WO_NUM — connects a work order (DT_LEAK_WORKORDERS) to its status history and its type-specific detail form (repair, monitoring, emergency, surveillance).

See the for the full picture drawn as a map.

SELECT l.LEAK_ID, l.GRADE, l.STATUS, wo.WO_NUM, wo.WO_STATUS FROM DT_LEAKS l JOIN DT_LEAK_WORKORDERS wo ON wo.LEAK_ID = l.LEAK_ID WHERE l.STATUS <> 'CLOSED';

Querying in Snowflake — three things to know

  • Use fully qualified names if the database isn't set in your session: PROD_GDM_PROD_DB.<schema>.DT_LEAKS. Check the schema name in Snowsight's object browser.
  • Quote column names that contain spaces. Some columns in VW_LEAKS_BACKLOG (like "BACKLOG YEAR") need double quotes, written exactly as-is, or the query errors.
  • Freshness is automatic. The DT_ objects are Dynamic Tables that refresh on a schedule — check SOURCE_REFRESH_DT in a table if you need to confirm how current a row is.

Want the full column dictionary? This catalog highlights key columns only. Run this in Snowsight to list every column, type, and comment for all 13 objects — and if the team maintains COMMENT descriptions in Snowflake, they'll appear here too:

SELECT TABLE_NAME, ORDINAL_POSITION, COLUMN_NAME, DATA_TYPE, IS_NULLABLE, COMMENT FROM PROD_GDM_PROD_DB.INFORMATION_SCHEMA.COLUMNS WHERE TABLE_NAME IN ( 'DT_LEAKS','VW_LEAKS_BACKLOG','DT_LEAK_EXTENT','DT_LEAK_GRADE_HIST', 'DT_LEAK_READING','DT_LEAK_STATUS_HIST','DT_LEAK_WORKORDERS','DT_LEAK_WO_STATUS_HIST', 'DT_WO_LEAK_EMERGENCY_ODOR_INVES','DT_WO_LEAK_MONITORING','DT_WO_LEAK_REPAIR', 'DT_WO_LEAK_REPAIR_OBSERVATION','DT_WO_LEAK_SURV_WALLCHECK_RECHE') ORDER BY TABLE_NAME, ORDINAL_POSITION;

What is leak data Draft

Leak Data is the set of records generated and maintained across the full lifecycle of a gas leak — from initial discovery through classification, response, repair, and closure. It answers: where and when was a leak found, how severe is it, what work has been done about it, and what is its current status?

In practice this covers four things:

  • The leak itself — location, grade, status, cause
  • Field readings & grading history that justify its classification
  • Work orders raised against it — emergency response, monitoring, surveillance, repair — each a distinct order type with its own detail form
  • The audit trail of every status and grade change

Together these support day-to-day field operations (dispatch, crew assignment, compliance tracking) and regulatory/backlog reporting (e.g. ).

Source systems Draft

PLATFORM
Snowflake — the mart is built as Snowflake Dynamic Tables and views inside PROD_GDM_PROD_DB. Dynamic Tables refresh themselves automatically from their source on a schedule (their "target lag"), so the data stays current without manual loads.
OPERATIONAL
IBM Maximo work & asset management — status codes (WAPPR, WSCH, FLDCOMP, CLOSE, CAN, ASBUILT) and the MAXADMIN system user match Maximo's standard vocabulary.
FIELD LAYER
Columns like SF_ORDERTYPE / SF_WONUM come from a Salesforce Field Service dispatch layer upstream of Maximo.
REFRESH
Extracted into PROD_GDM_PROD_DB on a scheduled refresh, tracked via SOURCE_REFRESH_DT / NGMOD_DT / NGLOADDATE.
CAPTURE
Field crews record leak-response and repair detail through structured digital forms per work-order type, which land in Maximo before extraction into this mart.

Leak grades (industry-standard convention)

Grade 1

Hazardous — requires immediate action.

Grade 2 / 2A

Potentially hazardous — scheduled repair or periodic monitoring within a defined window.

Grade 3

Non-hazardous at time of detection — re-evaluated on a monitoring cycle.

Exact repair/monitoring timelines are set by each jurisdiction's regulator and internal procedure — not shown in this data.

Glossary — plain-English terms for newcomers

Grain
What one row in a table represents (one leak, one reading, one status change). Always check the grain before counting or joining.
Dynamic Table (DT_)
A Snowflake table that refreshes itself automatically from its source query on a schedule — no manual loading. Its refresh frequency is called the "target lag."
Quoted identifiers
A Snowflake rule: column names containing spaces (like "BACKLOG YEAR" in the backlog view) must be wrapped in double quotes in SQL, exactly as written, or the query fails.
View (VW_)
A computed result built from other tables — e.g. an aggregation like the monthly backlog counts.
Leak grade
The severity classification of a leak: Grade 1 (hazardous, act immediately), Grade 2/2A (potentially hazardous, scheduled), Grade 3 (non-hazardous, monitored).
Work order (WO)
A dispatched job — an emergency response, a monitoring visit, a repair, or an inspection. Each has a type-specific detail table.
Backlog
Open leaks that haven't been repaired yet — the number regulators track month over month.
Jurisdiction / OPCO
The regulatory region (UNY, NYC, LI, MA) and the operating company code (5210–5330) that owns the asset. See the OPCO table above.
Maximo
The IBM work-management system that is the operational source of the work-order data.
LEAK_ID / WO_NUM
The two join keys that connect nearly everything: leaks to their detail, and work orders to theirs.
